## 一、这是什么

把用户在语雀写的 PRD「IM服务群PRD」+ 墨刀原型，转成**单文件离线 HTML 审阅页**，给前端/后端开发看。

核心诉求原话：

> 「我先按照git的文件版本创建文件，接下来我需要你来给我把一个文档转换成HTML格式，主要使用场景是给开发看产品说明文档，因此产物就是PRD + HTML转化的原型」（m00001）

页面是**三栏**：

```
┌──────────┬───────────────────────┬──────────────────┐
│ PRD 章节  │      原型截图          │  该节点的 PRD 正文 │
│ 1~8 章    │   （只放截图）          │   （完整原文）     │
└──────────┴───────────────────────┴──────────────────┘
```

用户对三栏的定义原话：

> 「最左侧依然是功能描述 中间放原型截图 最右侧放PRD」（m00976–m00978）

## 二、最重要的六条铁律（违反任何一条都会被退回）

### 1. 内容一个字都不许改

> 「内容不要变换，你对照语雀的内容，然后把内容逐一的输出出来」（m00648）
> 「除了刚刚我给你的这个链接，其他内容坚决不允许改」（m03559）

**只做「搬运 + 排版」，不做「编辑」。** 不改写、不精简、不补写、不重排、不统一术语。

- 加粗只处理原文已有的 `**`，原文没写的不加（m00665 裁定「做法甲」）。
- 冒号必须按原文还原（m02874）—— 曾因 `kvSplit()` 丢冒号被退回。
- 序号必须按原文还原（m03104 / m03160）—— 曾因自行加序号、漏掉 `1.` 被连退两次。

### 2. 编号保持语雀原文

> 「A. 保持语雀原文编号（8.1.2 处理人端、8.2 WEB 端）」（m01052）

第 8 章层级固定，**不许重新编号**：

```
8.1 APP 端功能描述
  ├─ 8.1.1 首页 -- 非处理人   （8.1.1.1 ~ 8.1.1.13）
  └─ 8.1.2 处理人端           （8.1.2.1 ~ 8.1.2.3）
8.2 WEB 端功能描述
  ├─ 8.2.1 聊天控制台
  ├─ 8.2.2 分流配置
  ├─ 8.2.3 群聊管理
  ├─ 8.2.4 配置模板
  ├─ 8.2.5 敏感词管理
  └─ 8.2.6 消息推送
8.3 POS 端功能描述
  ├─ 8.3.1 单店铺群
  └─ 8.3.2 多店铺群
```

⚠️ **「处理人端」是 8.1.2，不是 8.2。** 历史上有过误判。

### 3. 一个层级一个层级，不许大杂烩

> 「一个层级一个层级放内容，千万不要大杂烩一锅炖，全部放在一个地方，点哪里就是哪里的内容，而不是瞎放」（m01043）
> 「你就按照一个目录级下的内容放进去截图 + PRD就可以了，别瞎搞」（m01052 / m01063）

- 点哪个节点 → 中间只显示**该节点的截图**，右侧只显示**该节点的 PRD 正文**。
- 父节点不能把子节点的内容也吞进来。

### 4. 交互必须保留 `data-go`

> 「data-go一定要保留，这个页面交互还是需要的」（m00429）

模板的交互是两套：`data-page`（左栏 tab）+ `data-go`（画布内按钮），都保留，共用同一个 `render(page)`。

### 5. 模板原件不许动

`templates/review-template.html`（9828 字节）是**基准骨架**，一次都没改过。所有改动只发生在交付副本里。
模板有 3 处写死的字面量（第 46/47/48 行：`' · 待审阅 · 模板示例'`、`'验收行为草案'`、overview 的 `data-go="list"`），交付时要处理掉，但**原件保留原样**。

### 6. 用户不懂前端语法，前端细节由 AI 判定

> 「我不太能理解前端HTML的语法格式，因此真的要对ai做出指令，需要你来断定前端如何执行」（m00331）

所以：**不要问用户抽象的技术选项**（「你想要 A 方案还是 B 方案」），用户无法想象。**直接做出来给他看**，他看效果指问题。他明确说过：

> 「这个模板怎么样就是怎么样的」（m00432）
> 「你先改，有歧义的再说」（m00432）

### 3.3 解析器 `_tmp_parse_v4.js` 的关键结构

**起点**：`const START = 335;` → `_tmp_prd_fresh.md` 第 336 行 `# 功能描述`（第 8 章开头）。

**输出 JSON**：

```json
{
  "chapterHead": "<div class=\"q\">…提示音链接…</div>",
  "appInfoBlock": "<div class=\"info\">…需配合原型观看…</div>",
  "nodes": [ { "num":"8.1.1", "title":"首页 -- 非处理人", "level":3, "line":353,
               "path":"", "parent":0, "children":[1,2,…],
               "imgs":["…"], "imgKeys":["k0","k1"], "html":"<p>…</p>",
               "contentHtml":"…", "cardCount":0 } ]
}
```

**必守的渲染顺序**：正文用 `blocks` 数组严格按原文出现顺序 push：

```js
blocks.push({t:'path'|'p'|'list'|'table'|'quote'|'sub', html:'…'});
n.html = blocks.map(b => b.html).join('');
```

⚠️ 曾经的做法是「所有表格先抽出来统一放最前、小标题统一放后」，导致 `页面路径 → 痛点 → 目标 → 原型 → 筛选项 → 表格 → 操作项` 的交替顺序全乱，被用户退回（m01585）。

**父节点边界必须严格**——父节点只能读自己那一节，读完就停：

```js
let stop = n.to;
for (const ci of n.children) if (nodes[ci].from < stop) stop = nodes[ci].from;
const lines = L.slice(n.from + 1, stop);
```

⚠️ 不加这个 `stop`，`8.1` 会吞掉 291 张卡片、`8.1.1` 吞掉 207 张。

**其他要点**：

- `FIELDS = ['版本迭代','需求说明','注意边界','交互说明','热区范围','修订时间','备注']`
- `ANCHOR_MAP`（语雀站内锚点 10 个 key）：
  `dwXsx`→已读未读、`NcHLr`→个人设置、`bjkZk`→聊天记录、`DaXmu`→收藏、`BDber`→置顶公告、
  `d32SJ`→语音视频、`VFjl0`→群成员弹窗、`yre2R`→快捷回复、`uLAHZ`→私聊、`pOOl9`→多选转发
  ⚠️ `dwXsx` 必须映射到 `'已读未读'`（无斜杠，即 8.1.1.4），映射成 `'已读/未读'` 会命中 8.1.1.11.2.1 自己形成自环。
- `inline()` 里必须保留 `[文字](url)` → `<a href target="_blank" rel="noopener">`，但要过滤掉所有图片地址（三道正则，实测 `cdn.nlark.com` 出现 0 次）。
- WEB 端（`8.2` 开头）表格内嵌图片转 `〔图片：PSn〕` 标签；APP/POS 端不动。

### 3.4 构建器 `_tmp_build_ch8.js` 的关键结构

读取 v0.1.0 的 HTML 作基底，注入 tab / CSS / `render()` / lightbox，输出 v0.2.0。

**注入的变量**（`mergeJs`，第 660+ 行）：`CH8PAGES`、`CH8COUNT`、`CH8TREE`、`CH8_HEAD`、`CH8_APPINFO`
⚠️ **五个都要注入**。少注入一个，浏览器端运行时就会 `ReferenceError`，表现为「点功能页进不去详情」。8.1/8.2 目录页因为走 `if(data.isToc)` 早退分支，天然绕开报错行，所以这个 bug 极难发现——必须靠 `_tmp_sim_all.js` 运行时验证。

**树的渲染**（`treeHtml()`）：扁平行，不用嵌套 `<ul>`：

```js
'<div class="ch8row d' + depth + '" style="padding-left:' + (depth*18+10) + 'px">'
```

depth 0–4 → padding 10 / 28 / 46 / 64 / 82 px，同级严格对齐。

**关键 CSS 数值**（全部 `!important`）：

```
body 15px / .ch8toc 13px / .ch8go 13px / .ch8num 12px / .prdbody 13px
table.tbl 12.5px / td.c-name 13px / .c-ver,.c-time,.c-short 11.5px
#prototype .tocli.lv4{padding-left:88px} / .lv5{padding-left:110px}
body.no-prd .layout{grid-template-columns:190px minmax(360px,1fr)}
body.no-prd aside{display:none}
body.no-prd #expand{display:none}
```

**字号换算是易错点**：用户说「加大两个字号」= **每处 +2px**，不是 2 倍。历史上误做成 `body 30px` 被要求「改回去」（m02410），后来又把 +2px 理解成 17px 基准、再到 16px、最后回到 15px 原始大小。

## 七、踩过的坑（这些坑都真踩过，别再踩）

### 7.1 正则与解析

1. **正则灾难性回溯**：`/^(?:\*\*)?([^*#|>][^:：]{1,12})(?:\*\*)?[：:]\s*$/` 在大文档上直接把 Node 挂死（>120 秒）。大 Markdown 用 `indexOf` / `startsWith` 逐行扫，不要用复杂正则。

### 7.2 PowerShell 与中文

2. **`Set-Content -Encoding UTF8` 毁中文**：写含中文的文件用 `write` / `edit` 工具，不要走 PowerShell 管道（曾出现 `鍘?tab` 这种乱码）。
3. **`Get-Content -Raw` + `.Replace()` + `Set-Content`** 同样毁中文。
4. **`node -e "...$..."`**：PowerShell 会吞掉 `$`，写成 `.js` 文件再跑。
5. **`node -e "...正则含 \\\" ..."`** 必然 SyntaxError（`Unterminated regexp literal`）→ 写 `.js` 文件。
6. **`git commit -m "带引号"`** 在 PowerShell 里会断，用 `git commit -F <临时文件>`。
7. **`[System.IO.File]::ReadAllBytes('相对路径')`** 忽略 `cd`，必须绝对路径。

### 7.3 校验时的假阳性 / 假阴性

8. **核对内容时必须还原冒号**：`<b class="k">键</b><span class="v">值` 要拼回 `键：值` 再比对，否则误报 78% 缺失。
9. **统计 HTML 里的 `class="x"` 时**，若该 HTML 在 JS 字符串里，实际是 `class=\"x\"`，直接搜 `class="x"` 得 0 是**假阴性**。
10. **`JSON.parse('"' + 已转义片段 + '"')`** 双重转义必然报 `Unexpected non-whitespace character after JSON at position 15`。
11. **拆分产物里的 `var CH8PAGES=...`** 时，结束标记是 `;\nvar CH8COUNT=`，不是 `;Object.keys(CH8PAGES)`（后者在文件末尾附近，会切出 439552 字符的片段并解析失败）。
12. **只匹配纯数字的键会漏掉 `chapter8`**，看起来像「页面丢了」。

### 7.4 改动的边界

13. **移除文案别用全文 `replace` 兜底**：`H.replace(/\s*待审阅\s*/g,' ')` 会误伤大图查看器的 script，导致 `Unexpected token '<'`。
14. **改完必须重建**：曾出现「源码改了但没跑构建」，用户看到的还是旧产物，白费一轮（m03497 → m03518）。
15. **别自作主张改用户没要求的地方**：m03559「除了刚刚我给你的这个链接，其他内容坚决不允许改」。即使看到排版有问题，也要先说明再改。
16. **`aside` 自带 `display:block`**，会盖过 HTML 的 `hidden` 属性，隐藏右栏必须写 `body.no-prd aside{display:none !important}`。
17. **`.gitignore` 要写全扩展名**：初始只写 `_tmp_*.js/json`，漏了 `_tmp_*.md` 导致 `_tmp_prd_fresh.md` 仍被跟踪。

### 7.5 沟通

18. **用户说「加大两个字号」= 每处 +2px**，不是 2 倍（m02613「文本加大两个字号不是两倍」）。
19. **不要问用户抽象的方案选项**——他无法想象。直接做出来给他看。
20. **用户说「算啦/不用了」不是放弃需求，是换方案**。例：高清图诉求（m01923）→「算了，不用了，你把图片放成那种可以点击查看的形式」（m02610）。要抓住他真正想要的是「便于开发查看」。
